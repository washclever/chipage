# 제작 설계 (2026-11-11, 두 번째 판)

연출 컨셉(`연출-컨셉-위는-설계-아래는-대장간.md`)을 실제로 돌아가는 홈페이지로 만든 방식이다. 첫 판(고속 비교기)의 설계는 `archive/v1/제작-설계.md`에 있다. 어디까지 됐는지는 `진행-상황.md`에 있다.

- 2026-11-11에 3D가 실시간으로 돌고 WebGPU를 쓰게 하라는 지시가 있었다. 그래서 미리 구운 필름을 넘기던 방식을 실시간 렌더링으로 바꿨다(4절). 시간표, 회로, 문구, 2D 위층은 그대로다.
- 굽는 방식(5, 6절)은 이제 컨셉 그림과 견줄 기준 그림에만 쓴다.
- 같은 날, 오프닝을 두 시안으로 만들고 LOD, 관성 회전, 커서 분해, 무지갯빛 재질, 덜 주황색인 제조 장면을 넣으라는 지시가 이어졌다. 시안의 내용은 `연출-시안-A-B-호수와-담금질.md`에 있고, 만든 방식은 이 문서 3절과 4절에 있다.

- 그 뒤 오프닝을 망치로 정했고, 재질·입자·카메라·로딩·상호작용을 다시 짰다. 문구와 배경과 물도 바꿨다. 화면에서 무엇이 어떻게 보이는지는 `연출-망치-필름.md`에 있다. 아래 표는 그 판에 맞춰 고쳤다.

## 1. 한 줄

스크롤 위치 하나(g, 화면 단위)가 전부를 정한다. g에서 카메라와 장면 상태가 나오고, GPU가 그 상태를 매 프레임 그린다. 같은 카메라로 그 위에 2D 효과와 이름표를 얹는다.

## 3. 시간표 (`film.js`)

박자는 "머무름(hold)"과 "이동"이 번갈아 온다. 이동은 앞 박자의 끝 상태에서 자기 끝 상태로 부드럽게 간다. **카메라는 박자마다 따로 잇지 않는다**: 지나가는 자리 전부를 한 줄의 곡선(지나친 값이 생기지 않는 3차 곡선)으로 이어서, 머무는 동안의 느린 흐름과 이동이 끊기지 않는다(`camAt`). 카메라는 여덟 숫자다(옆, 높이, 거리, 목표 x y z, 화각, 롤). 전체는 24.8 화면이다. 전체 길이는 시안 A가 23.4 화면, 시안 B가 24.5 화면이다. 오프닝만 시안마다 다르고(`OPENING.a`, `OPENING.b`), `cell`부터는 같은 박자다(`REST`).

| 박자 | 길이 | 내용 |
|---|---|---|
| open, hammer, quench | 0.9, 1.8, 1.3 | 모루 위에서 달아오르는 칩(층이 떠 있다). 망치 세 번에 층이 다져진다. 호수에 잠긴다 |
| lake | 1.0 | 호수 위의 로고, 입력 상자, 글자가 쳐진다 (`ORDER`) |
| cast | 1.2 | 글자가 불꽃으로 튀어 첫 셀이 된다. 카메라는 물에서 떠올라 기울며 셀 위로 내려간다 (`CAST`) |
| cell | 0.5 | 한 칸 |
| stamp | 1.2 | 셀이 찍혀 나가고 주변 회로가 그려진다. 카메라가 물러나는 만큼만 찍힌다 |
| schem | 1.1 | 회로도 전체. 시뮬레이션이 한 줄씩 읽는다 |
| fan, cands, back | 0.8, 1.0, 0.7 | 물러나면 후보 여럿. 고르고 돌아온다. 물밑에 다이의 격자가 비친다 |
| swell, flat, stand | 0.7, 0.3, 1.0 | 선이 면이 되고(평면 배선도), 층이 떠오른다 |
| gds | 1.0 | 빛의 입체 배선 |
| fan2, lcands | 0.7, 0.9 | 배치 후보 여럿, 선택 |
| down, land | 1.3, 0.4 | 설계가 물 위 46에서 내려오고, 호수가 물가에서 안쪽으로 굳어 웨이퍼가 된다 |
| build | 3.3 | 여섯 층. 층마다 붓고(28%) 깎고(58%) 식힌다 |
| cool, chip | 0.5, 1.1 | 몸통이 닫히고, 전원이 들어오고, 한 줄씩 쓴다. 포인터를 대면 부품이 풀려 떠오른다 |
| out, end | 1.1, 1.0 | 물러나면 웨이퍼 전체 |

상태에 새로 들어간 값: `objPos`(칩이 있는 곳. A의 오프닝에서는 대장간 안), `water`(1 호수 … 0 웨이퍼), `grid`(물밑의 격자), `ripple`(물결), `furn`·`glare`·`fbeam`(대장간의 불, 문의 눈부심, 안의 빛줄기), `aur`(하늘의 빛), `cold`·`emb`(불씨가 식은 정도와 양), `heat`·`flash`·`hammer`·`plinth`·`steam`(시안 B), `glass`(유리 블록의 유무), `pour`(붓는 정도).

화면이 바뀌지 않는 채 상태만 바뀌는 곳: `lake`의 시작(A에서는 문 안의 칩이 불빛에 묻힌 뒤, B에서는 칩이 물에 잠긴 뒤에 사라진다)과 `back`·`down`의 끝(이미 꺼진 후보를 정리한다).

## 4. 실시간 렌더러 (`stage.js`, `world.js`, `shade.js`)

three.js r186의 `WebGPURenderer`로 그린다. 셰이더는 전부 TSL로 써서 WebGPU에서는 WGSL로, WebGL 2에서는 GLSL로 컴파일된다. WebGPU가 없는 브라우저에서는 three.js가 알아서 WebGL 2로 그린다. 매 프레임 `state(g)`의 값을 유니폼에 넣을 뿐이라, 어느 스크롤 위치에서나 같은 그림이 나오고 거꾸로 넘겨도 그대로 거꾸로 돈다.

경로 추적기(`pt2.js`)의 장면을 래스터화에 맞게 다시 지었다.

| 경로 추적기에서 | 실시간에서 |
|---|---|
| 회로도 선의 거리 텍스처 | 선분마다 판 하나(인스턴스 4,890개). 조각 셰이더가 선까지의 거리로 2픽셀 남짓의 선과 번짐을 그린다. 셀이 바깥으로 찍혀 나가는 것, 주변 회로가 배열에서 바깥으로 그려지는 것, 방금 그은 곳이 뜨거운 것, 시뮬레이션이 한 줄씩 읽는 것도 같은 식으로 픽셀마다 계산한다 |
| 선에서 상자로 섞이는 거리 함수 | 레이아웃 상자마다 인스턴스 하나(6,597개). 상자는 자기가 자라 나올 선을 안다(`memory.js`의 `pairs`). 정점 셰이더가 `morph`에 따라 선 → 회로도 평면에 누운 상자 → 제 높이의 상자로 옮긴다. 아래층부터 오른다 |
| `buildY` 위는 빛, 아래는 금속 | 같은 상자를 재질 둘로 그린다. 빛의 재질은 `buildY` 아래를 버리고 금속은 위를 버린다. 쓰는 빛의 띠는 `buildY` 바로 위에 있다 |
| 빛의 상자(유리) | 더하는 빛. 모서리가 빛나고 비스듬한 면이 빛을 받는다(층마다의 색). 화면에서 몇 픽셀밖에 안 되는 상자는 모서리 대신 옅은 채움을 쓴다. 풀려 뜬 만큼, 그리고 포인터가 지나간 자리에서 더 밝다 |
| 금속 | PBR 금속(`MeshPhysicalNodeMaterial`). 층마다 금속이 다르다(`look`: 어두운 실리콘, 붉은 게이트, 금빛 플러그, 아래의 구리, 위의 옅은 알루미늄). 마감(2026-11-12): 판판하게 닦인 금속에 부품의 길이를 따라 고운 결(가까이서만, 반짝이지 않게), 부품마다 조금씩 다른 빛깔, 가장자리는 조금 더 매끄러워 윤곽이 비친 것을 받는다. 가로지르는 잔결과 윗금속의 서리는 없앴다(모래나 눈처럼 보였고 하얗게 떴다). 붓자마자 하얗게 달았다 식는다. 깎는 선이 막 지나간 곳의 열, 전원, 한 줄씩 쓰기, 1을 든 셀의 온기, 달궈짐(`heat`)과 타격의 번쩍임(맞은 자리에서 번진다). 얇은 막 간섭은 쓰지 않는다 |
| 유리 블록 | **칩의 몸통.** 얇은 막이 아니라 꺾는 고체다. 지금까지 그린 화면(`viewportMipTexture`)을 표면에서 다시 읽는데, 스펙트럼을 일곱 번(작은 화면 네 번) 나눠 빨강은 덜, 보라는 더 꺾어 읽는다. 표면은 모서리가 둥글고(둥근 상자 기하), 주조 유리의 느린 굴곡과 층의 이음매가 법선에 들어가 있고, 달궈지면 일렁이고, 타격의 고리가 지나간다. 모서리의 굴곡은 흐림(밉 단계)이다(서리와 포인터 자국은 2026-11-12에 없앴다). 반사는 PBR이 한다. 높이는 `buildY`와 `loose`를 따른다 |
| 금속판 붓고 깎기 | 판을 깎는 선(`wipe.x`)에서 잘라 그린다. 판은 은빛 쇳물이다: 흐르는 껍질의 틈으로만 열이 비치고, 잘리는 가장자리가 희다. 깎는 선에서 불꽃이 튄다(장면 안의 입자) |
| 후보 | 메시 14개. 메시마다 자리, 그리는 시간, 선택, 뒤집힌 배치를 물체 단위 유니폼(`onObjectUpdate`)으로 받는다. **LOD**: 후보는 줄인 기하를 쓴다(선은 길이 2 이상만 1,634개, 상자는 긴 변 2.4 이상만 1,177개). 우리 것만 전부 그린다 |
| 웨이퍼 전체의 칩 | 웨이퍼 위 다이 92개. 윗금속·금속 2·3·MIM 상자와 몸통 한 장, 얇은 유리. 우리 칩에서 바깥으로 번지며 쌓인다 |
| 커서 아래의 분해 | 상자의 정점 셰이더에서 한다. 부품마다 "얼마나 들렸는가" 값 하나: 포인터 가까이는 0.4~0.8, 가만두면 윗층에 지나가는 느린 너울만큼 조금. 그만큼 위로(높은 층일수록) 들리고, 포인터에서 멀어지는 쪽으로 미끄러지고, 그 방향을 가로지르는 수평축으로 바깥쪽이 들리며 조금 돈다(작은 부품일수록). 들려도 빛나지는 않는다(2026-11-12에 모서리의 찬 빛, 열린 아래층의 빛, 지나간 자리의 빛을 없앴다). 포인터의 자리는 시선이 칩의 덩어리(발부터 윗면까지)에 처음 닿는 곳이다. 마우스는 머무는 곳이고 그 자리와 세기를 `main.js`에서 두 번 늦게 따라가게 한다(0.16초, 0.22초). 손가락은 누르고 있는 곳이고 곧바로 따라간다(0.04초, 0.07초): 누르는 곳 자체가 갈라지고, 떼면 닫힌다 |

- 포인터: 어느 장면에서나 장면이 세로축을 중심으로 돈다. 포인터가 가리키는 각도(좌우 9°, 위아래 2.2°)로 스프링이 끈다(고유 진동 0.7 Hz쯤, 감쇠비 0.42: 늦게 따라가고, 조금 지나쳤다가 멎는다). 드래그하는 동안은 손을 따라 돌고, 놓으면 그때의 속도로 더 가다가 스프링에 끌려 돌아온다. ±30°를 넘으면 더 세게 당긴다. 지나간 자리는 잠깐 달아오른다. 터치와 "동작 줄이기"에서는 돌지 않는다.
- 품질: 작은 화면(긴 변 900px 미만이나 터치)에서는 MSAA와 반사를 끄고 불씨를 줄인다. 프레임이 26ms를 넘는 동안 해상도를 0.15씩 내리고(0.6까지), 12.5ms 아래로 한동안 있으면 0.1씩 올린다(1.5까지).
- 셰이더: 첫 프레임 전에 장면의 재질을 모두(모든 물체를 보이게 하고 시야 밖을 빼지 않고) 장면을 실제로 그리는 렌더 타깃에 맞춰 비동기로 컴파일하고(`compileAsync`), 컴퓨트 셰이더도 비동기로 컴파일한다(`compileComputeAsync`). `stage.js`의 `prepare`이고 `main.js`가 그것을 기다린다(20초가 넘으면 기다리지 않는다). GPU가 따로 컴파일하므로 로딩 그림이 멈추지 않고, 스크롤하다가 새 셰이더를 기다리며 멈추지도 않는다. 장면 뒤의 패스(블룸, 마지막 패스)는 첫 프레임에 컴파일된다. 그때는 그림이 다 그려져 멈춰 있어서 보이지 않는다.
- 실패: 그리다가 오류가 네 번 넘게 이어지면 장면을 접고 문구만 차례로 나오는 쪽으로 바뀐다.
- 확인용 주소(`?webgl`, `?probe`, `?loader`, `?hide=`, `?dpr=`, `?msaa=`, `?full`, `?debug`)는 README에 있다. 콘솔에서 `__site.blow()`로 망치의 타격을 일으킬 수 있다.

## 5. 굽기 (컨셉 그림과 기준 그림)

사이트는 더 이상 구운 프레임을 쓰지 않는다. 아래는 필름을 굽던 방식이고, 지금은 컨셉 그림이나 실시간 화면과 견줄 기준 그림을 구울 때 쓴다.

- 프레임은 386장, 1600×900 webp다. 머무름은 화면당 7장, 이동은 25장, 시뮬레이션과 쓰기는 따로 더 촘촘하다.
- **깎는 장면은 굽지 않고 가른다.** 층마다 "금속판이 덮인 그림"과 "깎고 난 그림" 두 장만 굽고, 페이지가 깎는 선을 따라 두 그림을 가른다. 선과 불꽃은 실시간이다. 그래서 선이 프레임 사이에서 끊기지 않는다. `frames()`에서 `wipe` 표시가 붙은 프레임이 "덮인 그림"이다.
- **포인터로 도는 프레임.** 장면이 멈춰 있는 두 곳(open, gds)은 카메라를 옆으로 돌린 그림을 다섯 장씩 더 굽는다(`o_<박자>_<n>.webp`).
- 구울 때 불씨는 넣지 않는다. 불씨는 전부 실시간이다.

```js
// http://localhost:4320 (렌더러), ready가 뜬 뒤 콘솔에서
const B = await import('/bake.js?' + Date.now());
await B.preview(6); /* 끝나면 */ await B.sheets()   // 여섯 장에 한 장씩 작게: renders/sheet_p*.jpg
await B.bake()                                      // 전부. 이미 있는 프레임은 건너뛴다
await B.bake({ redo: true, from: 53, to: 82 })      // 한 구간만 다시
await B.orbit()                                     // 포인터용 프레임 10장
B.progress()
```

`film.js`에서 박자의 길이나 프레임 수를 바꾸면 프레임 번호가 밀린다. 그때는 `site/frames/`를 비우고 전부 다시 굽는다. 박자 안의 값만 바꿨으면 그 구간만 다시 굽는다. RTX 3090에서 장당 12초쯤, 전부 한 시간 반쯤 걸린다.

## 6. 경로 추적기 (`pt2.js`)

- WebGL2 프래그먼트 셰이더 하나로 하는 경로 추적이다. 장면은 거리 함수다.
- 셀, 행, 열은 공간을 접어서 한 번만 계산한다. 접힌 경계에서는 걸음 길이를 따로 제한한다.
- 회로도에서 레이아웃으로: `d = max(mix(선까지의 거리, 상자까지의 거리, w), 드러남)`. 선은 거리 텍스처 한 장이다. 상자는 먼저 회로도 평면에 누워 있다가(평면 배선도) 층별로 제 높이로 올라간다.
- 설계 상태의 상자는 "빛의 배선"이다. 가장자리가 빛나고 빛이 그대로 통과한다. `buildY` 아래는 금속, 바로 위는 쓰는 빛이다.
- 깎고 쌓기: `carve = [x, 두께]`가 층 높이에 금속판을 놓는다. x보다 오른쪽만 남는다.
- 후보: 이웃 다이 자리에 같은 것을 다른 시간으로 그린다. `pick`이 오르면 고르지 않은 것이 붉게 식어 꺼진다.
- 셰이더를 고치면 컴파일에 1분쯤 든다. 값만 바꾸는 것은 컴파일이 필요 없다(`DEF`, `uK` 손잡이).
- 겪은 문제와 고친 방법은 `진행-상황.md`의 "렌더러에서 겪은 것"에 있다.

## 7. 페이지 (`main.js`, `fx.js`)

- 먼저 첫 화면의 작도 그림이 선 하나씩 그려진다(`#sketch`, 2D 캔버스, `sketch.js`). 그림은 작업자 스레드가 그리므로(`sketch.worker.js`), 그동안 three.js를 읽고 장면을 짓고 셰이더를 컴파일하느라 주 스레드가 막혀도 멈추지 않는다. 브라우저가 캔버스를 넘기지 못하거나 작업자가 실패하면 페이지에서 그린다. 장면이 준비되지 않았으면 그림은 끝으로 갈수록 느려지고(멈추지 않는다), 준비되면 0.45초 안에 마저 그린다. 그림은 바로 위에서 본 평면도이고, 장면의 첫 프레임도 같은 카메라다(`film.js`의 `TOP`). 그림이 끝나고 장면이 몇 프레임 그려지면 렌더러가 그 그림을 텍스처로 넘겨받고, 1.6초에 걸쳐 그림이 격자의 칸마다 칩에서부터 장면으로 열린다. 마지막 칸들이 열리는 동안(1.25초부터) 1.9초에 걸쳐 카메라가 위에서 첫 장면의 구도로 내려온다(그동안 스크롤하거나 누르면 나머지가 3.5배 빨리 지나간다)(높이를 먼저, 거리와 보는 곳을 그다음, 렌즈의 넓이를 마지막에). 문구는 0.8초 뒤부터 나타난다. 움직임을 줄이라는 설정에서는 로딩 연출 없이 바로 뜬다.
- 2D 위층은 장면 위에 놓인 캔버스이고 `screen`으로 겹친다. 그리는 것은 모두 "더해지는 빛"이다. 장면과 같은 카메라로 점을 화면에 옮긴다(`main.js`의 `P`).
- 로고와 입력 상자는 DOM이다. 입력한 글자는 캔버스에 그린다. 글자의 픽셀 자리에서 불씨가 떠나야 하기 때문이다. 그 픽셀 자리는 `fx.cast()`가 찾아 렌더러에 넘긴다(글자나 크기가 바뀔 때만).
- 포인터: 드래그로 잡고 돌린다, 놓으면 원래 각도로 돌아온다, 처음 모루 위의 칩과 칩과 서 있는 배선에서는 포인터 아래의 층이 갈라진다(빛나지는 않는다), 화면은 비틀지 않고 물을 젓는다(`fluid.js`: 수면은 그 압력대로 솟고 꺼지며 물결을 내고, 불씨와 불꽃은 흐름에 실린다), 그림이 조금 기운다, 입체 배선에서는 블록의 이름이 뜬다. 휴대폰의 손가락도 물을 젓고, 칩 위에서는 누르는 곳 자체가 갈라진다(스크롤하는 손가락도 포함되도록 터치 이벤트로 받는다).
- 세로 화면에서는 그림이 위쪽 띠에 놓이고 문구가 아래를 쓴다. WebGPU도 WebGL 2도 없으면 문구만 차례로 나온다.

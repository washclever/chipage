# 연출 시안 A·B: 대장간에서 호수로 / 달구고 두드리고 담금질 (2026-11-11)

- **지난 기록이다(2026-11-11).** 사용자가 시안 B(망치)로 정했다. 지금의 필름은 `연출-망치-필름.md`에 있다. 시안 A와 `?v=` 전환은 뺐다. 아래는 그때의 내용 그대로다.
- 상태(그때): **시안이다.** 사용자가 두 가지 오프닝을 각각 만들어 보라고 했고, 둘 다 돌아가게 만들었다. 어느 쪽으로 갈지는 아직 정해지지 않았다.
- 보는 법: 주소 끝에 `?v=a` 또는 `?v=b`. 화면 오른쪽 위의 `A` `B`를 눌러도 된다.
- 첫 셀이 그려진 뒤부터는 두 시안이 같은 필름이다. 다른 것은 오프닝과, 입력 문장이 회로도가 되는 방식이다.
- 승인된 컨셉 "위는 설계, 아래는 대장간"에서 바뀐 것은 5절에 있다.

## 1. 공통: 장소

대장간이 호숫가에 있다. 호수 위에서 설계를 하고, 그 호수가 웨이퍼가 된다.

| 것 | 화면에서 |
|---|---|
| 대장간 | 호수 건너편의 계단식 검은 덩어리. 높은 문 하나에 불이 차 있다. 층과 층 사이에 불빛의 이음매가 있고, 윗모서리가 하늘빛을 받는다(층을 쌓은 것처럼 읽힌다). 우리가 지은 모양이다 |
| 호수 | 별과 하늘빛, 대장간의 불, 회로도의 선을 비춘다. 지름이 웨이퍼와 같다 |
| 호수 → 웨이퍼 | 후보를 띄울 때부터 물밑에 다이의 격자가 옅은 빛으로 비친다. 설계가 내려올 때 물가에서 안쪽으로 얼음이 얼듯 굳어 웨이퍼가 된다(굳는 자리에 옅은 테두리) |
| 하늘 | 별, 지평선의 찬 빛, 대장간 옆 하늘의 옅은 빛의 장막 |
| 불씨 | 대장간과 모루 둘레에서는 뜨겁고, 호수 위 설계 공간에서는 식은 점이다. 카메라가 보는 곳 둘레에 늘 있다 |

## 2. 시안 A: 대장간에서 나와 호수로

| 박자 | 길이 | 내용 |
|---|---|---|
| open | 0.9 | 대장간 안. 유리 속의 완성된 칩이 모루(바닥에 박은 닦인 쇠 원판) 위에, 찬 빛줄기 아래 있다. 뒤로는 홀을 가로지르는 낮고 긴 화덕의 불. 바닥에는 화덕에서 모루를 돌아 문밖 호수까지, 회로의 배선처럼 꺾인 쇳물 홈이 나 있다 |
| leave | 1.7 | 카메라가 칩을 본 채 뒤로 물러나 문을 빠져나온다. 문설주가 화면 양옆에서 들어오고, 문 안은 불빛에 묻힌다. 물 위를 계속 물러나 호수 한가운데에 선다 |
| lake | 1.0 | 낮은 눈높이. 왼쪽에 대장간, 오른쪽에 열린 하늘. 호수 위에 Melange 로고가 뜨고 위로 물러난다. 입력 상자에 `make 64-bit memory!`가 쳐진다 |
| cast | 1.2 | 글자가 왼쪽부터 달아올라 **한 줄기 쇳물처럼** 모여 호수로 떨어진다. 카메라가 그 자리 위로 내려간다. 줄기가 닿은 곳에서 첫 비트 셀의 선이 바깥으로 흘러 퍼지고, 물에 고리가 번진다 |

## 3. 시안 B: 달구고, 두드리고, 담금질

| 박자 | 길이 | 내용 |
|---|---|---|
| open | 0.9 | 호수 한가운데 물 위로 솟은 모루. 그 위에 유리 없는 칩이 놓여 달아오른다(검붉은색에서 노란빛으로). 건너편에 대장간 |
| hammer | 1.5 | 망치가 세 번 내려친다. 맞는 순간 윗금속이 하얗게 달고, 불꽃이 튀고, 화면이 한 번 덜컥하고, 호수에 고리가 번진다. 카메라는 옆으로 돈다 |
| quench | 1.3 | 모루가 칩과 함께 물에 잠긴다. 김이 오르고, 물밑의 붉은 빛이 꺼져 간다. 카메라가 물러나 A와 같은 자리에 선다 |
| lake | 1.0 | A와 같다. 김이 아직 걷히는 중이다 |
| cast | 1.2 | 글자가 **불꽃으로 튀어** 위와 옆으로 흩어졌다가 호수 위로 내려앉는다. 불꽃이 닿는 대로 첫 셀의 선이 하나씩 나타난다 |

칩이 잠긴 그 자리에서 설계가 시작되고, 끝에서 그 자리에 다시 칩이 선다.

## 4. 이번 지시를 어디에 어떻게 넣었나

| 지시 | 넣은 곳 |
|---|---|
| 여러 개를 띄울 때 LOD | 후보 14개는 줄인 기하로 그린다. 선은 4,890개 중 1,634개(길이 2 이상), 상자는 6,597개 중 1,177개. 줌인·줌아웃의 대상인 우리 것만 전부 그린다. 웨이퍼 전체의 칩 92개는 윗금속층과 몸통 한 장씩이다 |
| 딜레이와 관성이 있는 z축 회전 | 장면이 세로축(층이 쌓이는 축)을 중심으로 돈다. 포인터가 가리키는 쪽으로 스프링이 끌어서, 늦게 따라가고 지나쳤다가 돌아와 멎는다(좌우 9°, 위아래 2.2°). 드래그하면 손으로 잡고 돌리고(±30° 남짓), 놓으면 돌던 힘으로 더 가다가 돌아온다 |
| 커서를 대면 그쪽 구조가 분해되어 보이는 것 | 칩이나 빛의 배선 위에 포인터를 올리면 그 둘레의 층이 위로 갈라져 올라간다. 높은 층일수록 많이 뜨고, 포인터에서 조금 벌어진다. 자리는 포인터를 늦게 따라가고, 갈라짐은 스프링으로 열리고 닫힌다. 완성된 칩(오프닝 A, 끝의 칩)과 서 있는 빛의 배선에서 된다 |
| 깎고 쌓는 것을 주황색으로만 때우지 말 것 | 부은 금속판은 주황 덩어리가 아니라 은빛 쇳물이다: 위의 찬 빛을 받아 빛나고, 움직이는 껍질의 갈라진 틈으로만 속의 열이 비치고, 얇은 막의 빛깔이 흐른다. 깎는 선은 찬 빛(흰색과 푸른색)이고 불꽃도 흰색에서 푸른색, 금색으로 간다. 막 놓인 금속은 식으면서 뜨임색(짚색, 자주, 파랑)의 띠가 지나간다. 층마다 금속이 다르다(어두운 실리콘, 붉은 게이트, 금빛 플러그, 구리, 알루미늄). 웨이퍼 바닥의 붉은 기운을 줄였다 |
| 반투명과 무지갯빛 | 유리 블록: 굴절, 분산(데스크톱), 면에 얇은 막의 무지갯빛, 모서리에 스펙트럼. 빛의 배선: 비스듬한 면에 층마다 다른 얇은 막의 빛깔. 웨이퍼: 가운데에서 가장자리로 고리 지는 얇은 막 빛깔(실제 웨이퍼처럼). 호수와 웨이퍼와 모루는 장면을 비춘다 |
| 처음에 반도체를 치우고 웨이퍼를 가져오는 것 | A: 칩을 대장간에 두고 나오고, 호수가 웨이퍼가 된다. B: 칩이 호수에 잠기고, 그 호수가 웨이퍼가 된다 |
| "메모리를 만들라"는 말이 회로도가 되는 것 | 글자의 픽셀 하나하나가 장면 안의 불씨다(3,600개). 화면의 글자 자리에서 떠나 첫 셀의 선 위에 내려앉는다. 호수에 비치고, 스크롤을 되돌리면 거꾸로 돈다. A는 쇳물 줄기, B는 불꽃 |

## 5. 승인된 컨셉에서 바뀐 것

- "위는 설계, 아래는 대장간"의 세로 이동(4,000 올라갔다 내려오기)이 없어졌다. 설계는 호수 위 46 높이에서 하고, 다 되면 그만큼 내려와 굳은 호수(웨이퍼)에 놓인다. 카메라가 물러나고 다가가고 눕는 것은 그대로다.
- 웨이퍼가 늘어선 홀과 웨이퍼마다의 빛기둥은 없어졌다. 배경은 호수, 대장간, 산, 하늘이다.
- 2D로 그리던 글자의 불씨와 첫 셀의 획은 장면 안으로 들어갔다.
- 그 밖의 박자(셀이 찍혀 나가기, 시뮬레이션, 후보와 선택, 선이 면이 되고 층이 떠오르기, 배치 후보, 깎고 쌓기, 칩, 웨이퍼 전체)는 그대로다.

## 6. 사용자가 정해 줘야 하는 것

1. A와 B 중 어느 쪽으로 갈지. 섞을 수도 있다(예: A로 열고, B의 불꽃으로 글자를 바꾼다).
2. 대장간의 생김새. 지금은 계단식 덩어리와 문 하나다. 더 가까이, 더 크게, 다른 모양으로 할 수 있다.
3. B에서 달구고 두드리는 대상. 지금은 완성된 칩(유리 없이)이다.
4. 하늘의 빛의 장막을 둘지. `film.js`의 `aur`를 0으로 하면 꺼진다.
5. 커서 분해가 되는 범위. 지금은 칩과 서 있는 배선에서만 된다.

## 7. 확인한 것과 못 한 것

- 그래픽 카드 없는 컨테이너에서 소프트웨어 렌더러로 보았다. WebGL 2로 두 시안의 박자마다 화면을 찍었고, WebGPU로는 화면 밖에 그려 읽어 내는 방식(`?probe`)으로 주요 박자를 그려 검증 오류가 없는 것을 보았다(데스크톱 품질 경로 포함).
- 포인터 회전은 드래그 뒤 각도가 돌아오며 지나쳤다 멎는 것을 숫자로 보았고, 커서 분해는 화면으로 보았다.
- 실제 그래픽 카드에서의 프레임 시간과 느낌(관성의 세기, 불꽃의 양, 밝기)은 보지 못했다. 이 값들은 실제 화면을 보고 맞춰야 한다.

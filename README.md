# 회사 홈페이지

투자자와 외부 창업자에게 회사를 소개하는 홈페이지다. 64비트 메모리 하나가 주문되고, 그려지고, 고르고, 배선이 되고, 웨이퍼 위에 쌓여 칩이 되는 과정을 스크롤로 본다. 홈페이지 코드, 연출과 제작 문서, 그림을 굽는 도구가 이 저장소에 있다.

- 레포: `washclever/chipage`(공개). `main`이 GitHub Pages로 나간다. 주소: https://washclever.github.io/chipage/
- 제품 저장소(Melange)와는 별개다. 이 저장소의 내용을 제품 저장소에 넣지 않는다. 제품의 웹 데모는 https://washclever.github.io/melange/ 에 있고, 홈페이지의 "데모" 버튼이 그리로 간다.
- 상태(2026-11-12): **망치 필름이 돌아가고, GitHub Pages에 올라가 있다.** 모루 위에서 달아오르는 칩, 망치 세 번, 호수에 담금질, 그 물 위에 로고와 입력, 글자가 불꽃이 되어 첫 셀, 회로도·검증·레이아웃·제조, 웨이퍼 전체. 장면은 three.js WebGPU 렌더러로 매 프레임 그린다(WebGPU가 없으면 WebGL 2). 실제 그래픽 카드에서 보고 맞추는 일이 남았다(`docs/진행-상황.md` 맨 위).
- 계획표와 컨셉 보드는 이 레포에 넣지 않는다.

## 보기

Node.js만 있으면 된다. 설치할 것은 없다.

```bash
npm start
```

브라우저에서 `http://localhost:4320/site/`를 연다. 영어는 `http://localhost:4320/site/?lang=en`.

- 처음에는 모루 위의 칩을 바로 위에서 내려다본 평면도(격자, 중심선, 칩의 모서리를 늘인 안내선, 칩 안의 층마다의 부품, 치수)가 그려지고, 그 위에 "반도체 칩 설계 자동화"가 뜬다. 그림은 따로 된 스레드에서 그려서, 장면을 짓고 셰이더를 컴파일하는 동안에도 멈추지 않는다(`site/src/sketch.js`, `sketch.worker.js`). 장면의 셰이더는 첫 프레임 전에 모두 컴파일한다. 장면이 준비되면 그림을 마저 그리고, 같은 위의 시점에서 그림이 격자의 칸마다 칩에서부터 장면으로 열린다. 그다음 카메라가 위에서 내려와 돌며 첫 장면의 구도로 들어가고, 그동안 호수 건너편이 열리고 대장간에 불이 붙는다.
- 끌면 장면이 손이 가는 만큼 돈다. 놓으면 원래 각도로 돌아온다(던지면 조금 더 가다가 돌아온다). 누르면 멈춘다. 도는 만큼 기운다. 휴대폰에서는 가로로 끄는 손가락이 돌리고, 위아래로 끄는 손가락은 페이지를 넘긴다. 마우스가 머무는 쪽으로도 조금 돈다.
- 물결은 물이 움직이는 대로 계산한다(`site/src/water.js`). 모루와 칩이 물속으로 가라앉을 때, 망치가 칠 때 물결이 인다.
- 포인터는 화면을 비틀지 않고 물을 젓는다(`site/src/fluid.js`). 시선이 물(나중에는 웨이퍼)에 닿는 자리에서 포인터가 간 쪽으로 물을 끌고(빠르게 저을수록 세다), 누르면 그 아래의 물을 밀어낸다. 저어진 물은 유체처럼 스스로 흘러 소용돌이로 말리고 느려지며, 수면은 그 압력대로 솟고 꺼져 물결을 내보내고, 그 위의 불씨와 불꽃은 흐름에 실려 간다. 휴대폰에서는 손가락이 같은 일을 한다. 처음 모루 위에서 달궈지는 칩, 칩, 서 있는 배선 위에 포인터를 올리면 그 자리의 부품이 들린다(빛나지는 않는다). 휴대폰에서는 손가락으로 누르는 곳이 갈라지고, 떼면 닫힌다.
- 콘솔에서 `__site.blow()`를 부르면 망치의 타격(불꽃, 철가루, 고리, 카메라의 반응)이 그 자리에서 일어난다. `?loader`는 `?probe`와 같이 쓸 때 로딩 연출을 켠다.

`site/` 폴더는 정적 파일뿐이라 어떤 정적 서버에 올려도 돈다(`index.html`, `src/`, `vendor/`). 구운 그림은 필요 없다.

- WebGPU로 도는 곳: Chrome과 Edge(113 이후), Safari 26 이후, Windows의 Firefox(141 이후). 그 밖에는 three.js가 알아서 WebGL 2로 그린다. 둘 다 없으면 문구만 차례로 나온다.
- 어느 쪽으로 도는지는 콘솔에서 `__site.stats()`의 `backend`로 본다.
- 확인용 주소 끝에 붙이는 것: `?webgl`(WebGL 2로 강제), `?dpr=1`(해상도 고정, 자동 조절 끔), `?msaa=0`, `?full`(작은 화면에서도 데스크톱 품질), `?hide=glass,embers,floor,…`(일부를 빼고 그림), `?probe`(화면 대신 렌더 타깃에 그려 2D 캔버스로 옮김. 헤드리스 브라우저에서 WebGPU를 볼 때), `?debug`(콘솔에 `__stage`), `?lang=en`.

## GitHub Pages

주소는 <https://washclever.github.io/chipage/>다. `site/`를 빌드 없이 그대로 올린다. 파일은 모두 상대 경로로 부르므로 이런 하위 경로(`/chipage/`)에서도 돈다.

- `main`에 올릴 때마다 `.github/workflows/pages.yml`이 `site/`를 Pages에 올린다. Actions 탭의 "Pages"에서 "Run workflow"로 직접 돌릴 수도 있다.
- 레포의 Settings → Pages → Build and deployment → Source는 "GitHub Actions"다. 회사 도메인을 쓰려면 같은 설정의 Custom domain에 넣는다.
- WebGPU는 HTTPS에서만 돈다. Pages는 HTTPS다.
- 이 레포는 공개다. 무료 요금제에서는 공개 레포여야 Pages를 쓸 수 있다. 그래서 `docs/`와 `renderer/`도 공개되어 있다.

## 읽는 순서

1. `docs/진행-상황.md`: 다음에 할 일(실제 그래픽 카드에서 보고 맞추기), 지켜야 할 것과 사용자 지시, 끝난 것, 알려진 문제.
2. `docs/연출-망치-필름.md`: **지금의 필름.** 장소, 만든 방식, 카메라, 망치, 문구, 확인한 것과 못 한 것.
3. `docs/연출-컨셉-위는-설계-아래는-대장간.md`: 승인된 연출(첫 셀 뒤의 전환은 지금도 이것을 따른다).
4. `docs/제작-설계.md`: 시간표, 실시간 렌더러, 페이지 구조.
5. `docs/연출-상호작용-업그레이드.md`: 다음에 올릴 연출과 상호작용의 전략(지키는 것, 만드는 방법, 단계, 프레임 예산, 사용자가 정할 것).

`docs/연출-시안-A-B-호수와-담금질.md`는 오프닝을 망치로 정하기 전의 기록이다.

## 폴더

| 폴더 | 내용 |
|---|---|
| `site/` | 홈페이지. `index.html`, `src/`(코드), `vendor/`(묶은 three.js와 그 라이선스) |
| `renderer/` | 개발 서버와 그림을 굽는 도구(경로 추적기) |
| `docs/` | 연출, 제작 설계, 진행 상황 |
| `.github/workflows/` | GitHub Pages에 올리는 워크플로 |

구운 그림(`renders/`, `site/frames/`)은 저장소에 넣지 않는다.

## three.js 다시 묶기

사이트는 `site/vendor/three.js` 한 파일(three.js r186의 WebGPU 빌드와 블룸, 1 MB, gzip 300 KB)을 쓴다. 판을 바꿀 때만 다시 묶는다. 묶은 파일 끝에 라이선스 고지가 들어가고, 전문은 `site/vendor/three.LICENSE.txt`에 있다.

```bash
npm install
```

```bash
npm run vendor
```

## 기준 그림 굽기

사이트는 구운 그림을 쓰지 않는다. 경로 추적기는 실시간 화면과 견줄 기준 그림을 구울 때 쓴다. WebGL2가 되는 브라우저와 그래픽 카드가 필요하다.

1. `npm start`로 서버를 띄우고 `http://localhost:4320`을 연다. 왼쪽 위에 `ready`가 뜰 때까지 기다린다(셰이더 컴파일 1분쯤).
2. 개발자 도구 콘솔에서 굽는다.

```js
const B = await import('/bake.js?' + Date.now());
await B.bake()                                   // 전부. site/frames/f_0000.webp ... 와 index.json. 이미 있는 것은 건너뛴다
await B.bake({ redo: true, from: 53, to: 82 })   // 한 구간만 다시
B.progress()                                     // 진행 상황
```

카메라와 장면의 시간표는 `site/src/film.js`다. 실시간 렌더러와 경로 추적기가 같은 시간표를 읽는다. 자세한 것은 `docs/제작-설계.md`.

헤드리스 브라우저로 보는 법은 `docs/진행-상황.md` 끝에 있다.

## 정리 규칙

- 시험 그림은 `renders/`에 `a_ c_ d_ e_ m_ p_ s_ t_ w_ x_ y_ z_ sheet_`로 시작하는 이름으로 저장한다. git이 무시한다.
- 문서는 `docs/`에 둔다. 사용자의 새 지시는 `docs/진행-상황.md`의 "사용자 지시" 절에 날짜와 함께 적는다.
- 회로는 `site/src/memory.js`, 카메라와 시간표는 `site/src/film.js` 한 곳에서만 고친다(카메라가 지나가는 자리도 여기 있다). 장소(호수, 대장간, 모루, 망치)는 `site/src/world.js`, 물결은 `site/src/water.js`, 포인터가 젓는 물은 `site/src/fluid.js`, 메모리와 재질과 후처리는 `site/src/stage.js`, 함께 쓰는 셰이딩 함수는 `site/src/shade.js`, 해시는 `site/src/hash.js`, 로딩의 작도 그림은 `site/src/sketch.js`다.
- 문구에는 반도체와 설계만 쓴다. 신화나 대장간의 말은 넣지 않는다.
- 다른 사이트나 작품의 코드, 그림, 구조를 옮기지 않는다. 외부 라이브러리는 라이선스를 지키고 고지를 함께 둔다.
- `site/src/copy.js`의 대괄호는 회사가 채울 자리다.
- 작업이 한 단계 끝날 때마다 커밋하고, 진행 상황이 바뀌면 `docs/진행-상황.md`를 고친다.
